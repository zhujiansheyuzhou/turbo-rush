# 02 概要设计说明书

**项目**：极速狂飙 Turbo Rush　**版本**：V1.0　**对应文档**：《01 需求分析报告》

---

## 1. 总体设计

### 1.1 设计目标
- 满足需求文档全部 FR/NFR；
- **逻辑与表现严格分层**：游戏逻辑不依赖 DOM 与渲染，可在 Node 中无头运行与自动化测试；
- 零构建、零外部资源：经典脚本 + 本地 Three.js，双击 index.html 即运行。

### 1.2 技术选型
| 决策点 | 选择 | 理由 |
|--------|------|------|
| 渲染 | Three.js r147（UMD 本地化） | WebGL 封装成熟；r147 是保留 UMD 构建的版本，可用经典 `<script>` 加载，file:// 直开 |
| 模块化方式 | 经典脚本 + 全局命名空间 `RACER` | 避免 ES Module 在 file:// 下的 CORS 限制，免服务器 |
| 美术资源 | Canvas 程序化贴图 + 盒体拼装模型 | 无外部图片 → 无跨域问题、无版权风险、体积小 |
| 音频 | WebAudio 振荡器程序合成 | 无音频文件，同上 |
| 持久化 | localStorage | 计时赛纪录，轻量够用 |

### 1.3 体系结构（分层架构）

```
┌─────────────────────────────────────────────────┐
│                  界面层 (DOM/CSS)                │
│   menu.js 菜单 · hud.js HUD · index.html 骨架    │
├─────────────────────────────────────────────────┤
│              表现层 (Three.js / WebAudio)        │
│   game.js 编排 · track.js 场景 · car.js 车模     │
│   audio.js 音效 · input.js 输入                  │
├─────────────────────────────────────────────────┤
│                逻辑层 (纯 JS，无 DOM)            │
│   racecore.js 比赛核心 · trackdata.js 赛道数学   │
│   physics.js 车辆物理 · ai.js AI 车手            │
├─────────────────────────────────────────────────┤
│         支撑层：config.js 配置 · utils.js 工具   │
│         外部依赖：three.min.js (r147 UMD)        │
└─────────────────────────────────────────────────┘
```

**关键规则**：依赖只能向下。逻辑层不知道 DOM/Three 渲染对象的存在（仅借用 `THREE.Vector3`/`CatmullRomCurve3` 做数学计算）；表现层通过读取逻辑层的状态做可视化，不修改规则。

### 1.4 为什么这样分层？
1. **可测试性**（NFR-04）：逻辑层可在 Node 中加载，`test/sim.js` 让 AI 扮演玩家无头仿真整场比赛，自动断言圈数、名次、物理稳定性；
2. **可维护性**（NFR-03）：改手感只动 `physics.js`/`config.js`，改画面只动表现层；
3. **职责清晰**：`RaceCore` 是唯一的规则权威（Single Source of Truth），表现层只是它的"摄像机"。

## 2. 模块设计

| 模块 | 职责 | 主要接口 |
|------|------|----------|
| utils.js | 数学工具、时间格式化、赛道俯视图绘制 | clamp/lerp/damp/wrapAngle/formatTime/drawTrackOutline |
| config.js | 全部静态配置（赛车 3 辆、赛道 2 条、键位） | RACER.CONFIG |
| trackdata.js | 样条离散采样；进度↔坐标互查；曲率查询 | pointAt/tangentAt/normalAt/maxCurvature/query/queryGlobal |
| physics.js | 单步车辆物理（速度分解模型） | CarPhysics.step(state, input, params, dt, surface) |
| ai.js | AI 驾驶输入计算（Pure Pursuit + 曲率刹车） | AIDriver.compute(state, params, u01, rubber, nitro, dt) |
| racecore.js | 比赛规则：进度/圈数/名次/碰撞/氮气/倒计时/结算 | step(dt)→events、getStandings()、resetPlayerToTrack() |
| input.js | 键盘采集，瞬时动作回调 | read()、onAction |
| audio.js | 程序合成音效 | init/setEngine/beep/thud/toggleMute |
| track.js | 赛道 3D 场景（路面/护墙/草地/树/龙门架） | Track(scene, trackDef).data |
| car.js | 车模、车轮动画、烟雾粒子、氮气火焰、假阴影 | CarView.update(state, input, offroad, dt) |
| hud.js | HUD 刷新、小地图、中央提示 | update(core, carViews)、showMessage() |
| menu.js | 菜单流转、赛道预览、性能条 | onStart(cfg) 回调 |
| game.js | 编排：渲染器/相机/主循环/事件翻译 | startRace(cfg)、backToMenu() |
| main.js | 装配菜单与游戏 | — |

## 3. 核心数据流

```
键盘 ──→ Input.read() ──→ RaceCore.setPlayerInput()
                              │ step(dt)
                              ├→ CarPhysics.step()  （每辆车）
                              ├→ TrackData.query()  （进度/路面/护墙）
                              ├→ AIDriver.compute() （AI 输入）
                              └→ events[]（撞墙/过圈/完赛…）
                                    │
HUD.update ◄── carStates ◄──────────┘
CarView.update ◄── carStates          Game._handleEvents ──→ Audio/HUD 提示
相机跟随 ◄── player.state
```

## 4. 关键数据结构设计

### 4.1 车辆状态（逻辑层，纯数据）
```js
{
  name, spec, isPlayer,
  state: { x, z, heading, vF, vL, speed, drifting },  // 物理状态
  input: { steer, throttle, brake, handbrake, nitro }, // 本帧输入
  nitro: 0~100,
  lastIndex,            // 赛道采样点缓存（滑动窗口加速查询）
  progressTotal,        // 累计进度（圈为单位，可为小数/负数）
  lap, canCountLap,     // 圈数与半程点标记（防刷圈）
  lastLap, bestLap, finished, finishTime,
  ai: AIDriver | null
}
```

### 4.2 赛道采样点（TrackData.samples[i]）
```js
{ pos: {x, z},      // 中心线坐标
  tx, tz,           // 单位切线（前进方向）
  rx, rz,           // 单位右法线（侧向偏移/路面判定基准）
  kappa,            // 曲率（AI 刹车预判依据）
  dist }            // 累计弧长
```

## 5. 状态机设计

### 5.1 比赛状态机（RaceCore）
```
countdown ──3.6s──→ racing ──玩家完成全部圈数──→ finished
   │                  │  Esc                          │
   │                  ▼                               ▼
   │              （输入屏蔽）                    车辆巡航滑行
   └─ 期间输出 count 事件 → GO 事件           1.6s 后弹结算面板
```

### 5.2 应用状态机（Game/Menu）
```
menu（title→mode→track→car）──开赛──→ racing ──→ finished ──→ 结算
   ↑                                  │ Esc 暂停           ├→ 再来一局 → racing
   └────────── 返回主菜单 ◄────────────┴────────────────────┴→ 回主菜单
```

## 6. 接口设计（层间契约）

**表现层 → 逻辑层**
- `new RaceCore(trackData, { mode, playerSpec, aiSpecs, totalLaps })`
- `core.setPlayerInput(input)` 每帧注入玩家输入
- `core.step(dt)` → `events[]`；`core.cars` 读取全部车辆状态
- `core.getStandings()` → 名次排序后的车辆数组

**逻辑层 → 表现层（事件契约）**
| 事件 | 载荷 | 表现层动作 |
|------|------|-----------|
| count | { n } | HUD 显示数字 + 440Hz 哔声 |
| go | {} | "GO!" + 880Hz 哔声 |
| lap | { car, lap } | 玩家：圈数提示音与文字 |
| wall | { car } | 玩家：闷响 + 相机震动 |
| bump | { a, b } | 涉及玩家：轻闷响 |
| finish | { car } | 玩家："冲线！"，1.6s 后结算 |
| reset | { car } | "已重置回赛道"提示 |

## 7. 性能设计（对应 NFR-01）
- 赛道为静态几何：路面/护墙各 1 个 BufferGeometry（约 2400 顶点），树木共享几何体与材质；
- 阴影采用贴片假阴影（1 个半透明面片/车），完全避开阴影贴图开销；
- 烟雾为固定 26 个 Sprite 的对象池，零运行期分配；
- 进度查询采用滑动窗口（±12/+48 采样点）避免 O(N) 全表扫描；
- 主循环 `dt` 钳制 1/20s，掉帧不会导致物理爆炸。

## 8. 健壮性设计（对应 NFR-06）
- 失焦清空按键状态，防止"按键卡死"；
- 重置回赛道时清除半程点标记，杜绝"重置刷圈"作弊；
- 未过半程点越线不计圈并将进度回退到圈末；
- localStorage 访问 try/catch（file:// 某些浏览器禁用时不影响游戏）。
