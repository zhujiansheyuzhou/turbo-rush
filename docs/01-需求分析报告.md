# 01 需求分析报告

**项目名称**：极速狂飙 Turbo Rush —— 基于 Web 的 3D 街机赛车游戏
**课程**：软件工程 期末大作业
**版本**：V1.0

---

## 1. 引言

### 1.1 编写目的
本文档定义"极速狂飙"赛车游戏的功能性与非功能性需求，作为后续设计、开发与验收测试的依据。预期读者为项目开发人员与课程评审教师。

### 1.2 项目背景与目标
参考《极限竞速：地平线 4》等成熟赛车游戏的核心体验（驾驶手感、竞速对抗、漂移与氮气），在课程周期约束下实现一款**复杂度适中、完整可玩**的 3D 赛车游戏。选择 Web（Three.js）技术栈，使作品无需安装、浏览器直接运行，便于课堂演示与提交。

### 1.3 术语
| 术语 | 说明 |
|------|------|
| 街机物理 | 简化的车辆动力学模型，追求手感而非拟真 |
| 漂移 | 手刹降低侧向抓地力，使车身侧滑过弯的操作 |
| 氮气 | 可消耗的瞬时加速资源 |
| 橡皮筋机制 | AI 根据与玩家的差距动态调整水平，保持比赛悬念 |
| Pure Pursuit | 纯追踪算法，一种经典的路径跟踪控制方法 |

## 2. 总体描述

### 2.1 产品定位
单机 3D 街机赛车游戏。玩家选择模式、赛道与赛车后，在封闭环道上与 AI 竞速或独自计时。

### 2.2 用户特征
- 课程评审教师：关注完整性、可玩性、工程质量；
- 普通玩家：无赛车游戏经验也可在 1 分钟内上手。

### 2.3 运行环境
- 硬件：支持 WebGL 的普通 PC（集显即可流畅运行）；
- 软件：Chrome / Edge 等现代浏览器，**无需安装任何运行时或依赖**；
- 网络：无需联网（Three.js 库已本地化）。

### 2.4 约束
- 开发周期：课程周期内完成；
- 不使用游戏引擎（Unity/UE），采用 Three.js 原生开发以体现软件工程设计能力；
- 全部美术资源程序化生成，无版权风险。

## 3. 功能性需求

### 3.1 功能结构

```
极速狂飙
├── 菜单系统
│   ├── 标题界面
│   ├── 模式选择（竞速赛 / 计时赛）
│   ├── 赛道选择（含俯视图预览）
│   ├── 赛车选择（含性能条对比）
│   └── 操作说明
├── 比赛系统
│   ├── 倒计时发车（3-2-1-GO）
│   ├── 驾驶控制（油门/刹车/转向/手刹/氮气）
│   ├── 圈数与计时（分段计圈、最佳圈速）
│   ├── 名次判定（实时排名）
│   ├── AI 对手（3 名，差异化车型与水平）
│   ├── 碰撞（护墙 / 车际）
│   └── 暂停 / 重置 / 重开
├── 表现系统
│   ├── HUD（速度表/氮气条/圈数/名次/圈速/小地图）
│   ├── 特效（漂移烟雾/氮气火焰/相机震动/FOV 冲击）
│   └── 音效（引擎/倒计时/碰撞）
└── 结算系统
    ├── 竞速赛名次表
    └── 计时赛纪录（localStorage 持久化）
```

### 3.2 用例规约（核心用例）

**UC01 进行竞速赛**
- 主成功场景：玩家选择竞速赛 → 选赛道 → 选赛车 → 倒计时结束发车 → 完成 3 圈 → 显示名次表；
- 扩展流：2a. 玩家撞墙 → 速度损失并被护墙约束回赛道；3a. 玩家按 R → 车辆重置到赛道中心，本圈需重新通过半程点方可计圈（防刷圈）；4a. 玩家按 Esc → 比赛暂停，可继续/重开/回主菜单。

**UC02 进行计时赛**
- 主成功场景：玩家选择计时赛 → 独自跑 3 圈 → 显示最佳圈速，若打破本地纪录则提示"新纪录"并持久化。

**UC03 漂移与氮气**
- 玩家按住空格 + 方向键且车速足够 → 进入漂移状态（后轮冒烟、车身侧滑）；
- 漂移时氮气快速恢复；按住 Shift 且氮气 > 0 → 极速与加速度提升，伴随尾焰与 FOV 冲击。

### 3.3 功能需求明细（FR）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-01 | 提供标题、模式、赛道、赛车、帮助五级菜单 | 高 |
| FR-02 | 竞速模式生成 3 名 AI，使用不同车型与车道 | 高 |
| FR-03 | 街机物理：速度分解模型 + 抓地力衰减侧滑 | 高 |
| FR-04 | 手刹漂移：抓地力下降、烟雾特效、氮气加速恢复 | 高 |
| FR-05 | 氮气：储量 0-100，使用消耗/缓慢恢复，提升动力 | 高 |
| FR-06 | 圈数判定：基于赛道进度采样，需通过半程点防作弊 | 高 |
| FR-07 | 实时名次：按"圈数+圈內进度"排序 | 高 |
| FR-08 | 护墙碰撞约束与车际碰撞 | 高 |
| FR-09 | HUD：速度/氮气/圈数/名次/圈速/小地图 | 高 |
| FR-10 | 结算面板与再来一局/返回主菜单 | 高 |
| FR-11 | 倒计时发车（期间禁止输入） | 中 |
| FR-12 | 计时赛纪录 localStorage 持久化 | 中 |
| FR-13 | 程序化音效（引擎/哔声/碰撞），M 静音 | 中 |
| FR-14 | 暂停/继续/重置/重开 | 中 |
| FR-15 | 赛道选择预览图、赛车性能条 | 低 |

## 4. 非功能性需求（NFR）

| 编号 | 类别 | 需求 |
|------|------|------|
| NFR-01 | 性能 | 1080p 下稳定 60 FPS（集显）；单帧逻辑 < 8ms |
| NFR-02 | 易用性 | 无需安装、双击即玩；键位符合直觉；1 分钟内可上手 |
| NFR-03 | 可维护性 | 逻辑/表现分层；模块单一职责；全部代码中文注释 |
| NFR-04 | 可测试性 | 核心逻辑可无头仿真，自动化断言覆盖关键规则 |
| NFR-05 | 兼容性 | Chrome/Edge 最新版；file:// 与 http:// 均可运行 |
| NFR-06 | 健壮性 | 掉帧保护（dt 钳制）；失焦清空按键；数值无 NaN |

## 5. 验收标准
1. 浏览器打开 index.html，30 秒内可从标题界面进入一场比赛；
2. 竞速赛可正常完赛并给出正确名次；计时赛可刷新并保存纪录；
3. 漂移、氮气、碰撞、暂停、重置功能均按 FR 描述工作；
4. `node test/sim.js` 全部断言通过；
5. 游戏过程无脚本错误，帧率流畅。
